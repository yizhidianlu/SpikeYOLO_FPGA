# Proposed Contract Change v1.0.3 — B1 regmap extension (LAYER_ID / LAYER_MASK)

**Status**: DRAFT — awaiting B2 / C2 / D1 sign-off
**Author**: B1 HLS Kernel Agent (W5 prep)
**Date**: 2026-05-11
**Affects**: Contract 3 (B1 -> B2 IP package). Minor follow-up in Contract 5.

## Motivation

W4 landed `sa_tiny_fpga_top` (290 LoC dispatcher) supporting two modes:

- `layer_id = -1` -> run the full 11-layer pipeline (stem -> detect cast).
- `layer_id ∈ {0..11}` -> run a single layer (debug / per-layer bisection).

The dispatcher already plumbs this via a function arg, but the v1.0.2 regmap
declares `LAYER_ID` as `"0..11"` only, so PS cannot drive single-step debug
on real silicon. M2 board bring-up needs this on day 1.

We also want a **per-layer mask** for the M3 partial-pipeline benchmarks
("run layers 0..8 only, skip detect") without re-burning a bitstream.

## Proposed diff (against `docs/CONTRACTS.md` lines 165-183)

```yaml
ip_name: spike_accel_top
version: "1.0.3"                         # was "1.0"
clock_period_ns: 10.0

axi_lite:
  base: 0x0000
  size: 0x10000
  registers:
    - { addr: 0x00, name: CTRL,       bits: { 0: ap_start, 1: ap_done, 2: ap_idle, 3: ap_ready, 7: auto_restart } }
    - { addr: 0x04, name: GIE,        bits: { 0: global_irq_en } }
    - { addr: 0x08, name: IER,        bits: { 0: ap_done_irq_en, 1: ap_ready_irq_en } }
    - { addr: 0x0C, name: ISR,        bits: { 0: ap_done_isr, 1: ap_ready_isr } }
    # --- v1.0.3 change: widen LAYER_ID semantics ---
    - { addr: 0x10, name: LAYER_ID,   desc: "signed int32: -1=run all 12 layers, 0..11=single layer (debug)" }
    # --- v1.0.3 new register ---
    - { addr: 0x14, name: LAYER_MASK, desc: "uint32 bitmask, bit i set -> run layer i. Ignored when LAYER_ID != -1. Default 0x0FFF (all 12 on)." }
    # --- existing registers shift by 4 bytes ---
    - { addr: 0x18, name: H,          desc: "feature map height" }
    - { addr: 0x1C, name: W,          desc: "feature map width" }
    - { addr: 0x20, name: C_IN }
    - { addr: 0x24, name: C_OUT }
    - { addr: 0x28, name: IN_PTR_LO }
    - { addr: 0x2C, name: IN_PTR_HI }
    - { addr: 0x30, name: OUT_PTR_LO }
    - { addr: 0x34, name: OUT_PTR_HI }
    - { addr: 0x38, name: W_PTR_LO }
    - { addr: 0x3C, name: W_PTR_HI }
```

Note: `H`/`W`/`C_IN`/`C_OUT`/`*_PTR_*` slide up by 4 bytes. C2 driver must
re-read offsets from the autogenerated header — no hard-coded addresses.

## Backward compatibility

- Old PS code that wrote `LAYER_ID = 0..11` still works (single-layer debug).
- Old PS code that wrote LAYER_ID without writing LAYER_MASK gets the default
  `0x0FFF` -> the IP behaves identically to v1.0.2.
- `LAYER_ID = -1` is a **new** legal value; v1.0.2 PS code never wrote it.

### C2 sign-off notes (2026-05-11)

Implemented in `sw/sdk/include/spike_accel.h` + `sw/sdk/src/accel_drv.c`:

- Added `sa_set_layer_id(handle, int32_t)` — accepts `-1` and `0..11`,
  rejects everything else with `SA_ERR_INVALID_ARG`. Eagerly writes
  `LAYER_ID @ 0x10` on the real backend; caches in handle on stub.
- Added `sa_set_layer_mask(handle, uint32_t)` — refuses `mask == 0` (would
  silently idle the engine) with `SA_ERR_INVALID_ARG`. Default after
  `sa_open` is `0x0FFF` so existing PS code is bit-identical to v1.0.2.
- Updated `sw/sdk/src/internal.h` register offsets: `LAYER_MASK @ 0x14`,
  `H @ 0x18`, ..., `W_PTR_HI @ 0x3C` (everything from `H` onward shifted
  by +4 bytes per the proposal). No hard-coded address survives outside
  this header — all driver code uses the named macros.
- Library version bumped 1.0.0 -> 1.1.0. ABI is additive (two new
  exported symbols + two new tail fields in `sa_perf_t`), no symbol
  removed, no struct field reordered. `SOVERSION` stays at `1`.
- Three new ctest cases added to `sw/sdk/tests/test_api_contract.c`
  exercising layer-id round-trip, mask-zero rejection, and the
  `timeout_ms == 0` non-blocking-try contract.
