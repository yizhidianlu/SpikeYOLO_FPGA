# ADR-0003: Petalinux 2024.1 BSP source for ZYBO Z7-20

- **Status**: accepted
- **Date**: 2026-05-11
- **Deciders**: C1 Petalinux Agent (`C1-session-2026-05-11`, M1 W4)
- **Affected contracts**: implicitly C4 (consumes `address_map.yaml`)
- **Affected playbooks**: C1, C2, C3, D2

## Context

Petalinux 2024.1 needs a board-specific BSP to bring up the ZYBO Z7-20
(Z-7020 SoC, on-board DDR3 1 GB, on-board HDMI Tx PHY, USB OTG, Pmod, SD).
Three candidate sources exist; only one matches both the Vivado toolchain
already pinned by B2 (2024.1) and the on-board peripheral set.

| Option | Source | Pro | Con |
|---|---|---|---|
| **A** | Digilent `Petalinux-Zybo-Z7-20-2024.1-1.bsp` (github.com/Digilent/Petalinux-Zybo-Z7) | Board-vendor maintained; HDMI/USB/SD/Ethernet/I2C-EEPROM all enumerated; matches B2 ADR-0001 (`rgb2dvi` Tx); ships a working `system.dts` we can layer onto | Carries Digilent kernel patches (mainline lag ≤ 1 cycle); BSP file is ~600 MB and not vendored in-repo |
| **B** | Xilinx generic Zynq BSP + hand-written ZYBO Z7-20 dts | Fully vanilla; no third-party patches; smallest blob to vendor | Must enumerate every on-board pin / DDR3 timing / I/O bank voltage / HDMI clock domain manually — 3-5 engineer-days of work duplicating Digilent's effort, R7 (USB UVC) regression risk |
| **C** | Avnet ZYBO BSP | (none — Avnet stopped maintaining ZYBO at 2018.3) | No 2024.1 support, dead end |

## Decision

**Choose Option A — Digilent `Petalinux-Zybo-Z7-20-2024.1-1.bsp`**, layered
with this repo's `project-spec/meta-user/` overrides for the spike_accel
device-tree nodes, kernel config fragment, and `spike-accel-app` recipe.

Rationale:

1. Vivado 2024.1 ↔ Petalinux 2024.1 ↔ Digilent BSP 2024.1-1 are mutually pinned
   — no toolchain skew risk with B2's bitstream output.
2. HDMI Tx, USB OTG, SD root mount, console UART, I2C EEPROM, Ethernet PHY are
   pre-validated by the board vendor — eliminates the bulk of R7-class
   bring-up risk for free.
3. Digilent's `rgb2dvi` HDMI Tx demo dts matches B2's
   [`docs/decisions/0001_hdmi_tx_selection.md`](0001_hdmi_tx_selection.md)
   choice (`digilent,axi-hdmi` compatible string already wired).
4. Our PL-specific additions (`spike_accel`, `axi_dma_feat`, `vdma_disp`)
   layer cleanly via `meta-user/recipes-bsp/device-tree/` without forking
   the BSP.

## Consequences

- **`sw/petalinux/build.sh`** — main flow becomes `petalinux-create -t project
  --source ${PETALINUX_BSP} --name spikeyolo_petalinux`. Falls back to
  `--template zynq` when `--source` is absent, preserving the current default
  (still functional, just minus Digilent's HDMI/USB defaults).
- **`sw/petalinux/project-spec/meta-user/recipes-bsp/device-tree/files/spike-accel.dtsi`**
  *(new this sprint)* — adds `spike_accel`, `axi_dma_feat`, `vdma_disp`,
  `hdmi_tx` nodes with addresses + IRQs sourced from
  `hw/vivado/out/address_map.yaml`. Included from `system-user.dtsi`.
- **C2** — `uio_config.dts` (auto-generated by D2's `tools/ci/gen_dts.py`)
  continues to coexist; the new `spike-accel.dtsi` complements it for nodes
  that need vendor-specific drivers (DRM `digilent,axi-hdmi`, `xlnx,axi-vdma`)
  rather than UIO.
- **D1 / D2** — `petalinux-build` cannot run in GitHub-hosted runners (needs
  Petalinux SDK install + ~30 GB scratch + ~60 min wall time). M3+ requires a
  self-hosted runner (B2 and D2 already flagged this in `B2_W3_report.md`).
  Until then, `build.sh --dry-run` is the only CI gate.
- **License** — Digilent BSP is BSD-licensed, compatible with our MIT-licensed
  spike-accel-app. No license change to top-level repo.
- **Vendoring** — BSP is **not** committed to this repo (size + licence
  hygiene). Operators set `$PETALINUX_BSP` to point at a locally-downloaded
  copy. Path documented in `sw/petalinux/README.md` (next sprint).

## Fallback path

If Digilent BSP 2024.1-1 has unresolved blockers at M2 (e.g., kernel patch
conflicts with `CONFIG_PREEMPT_RT` for the R3 fallback), C1 falls back to
Option B (Xilinx generic + hand-written dts). Estimated cost: 3 engineer-days,
all confined to `meta-user/recipes-bsp/device-tree/files/system-user.dtsi`
and `recipes-bsp/u-boot/`. No contract change required.
