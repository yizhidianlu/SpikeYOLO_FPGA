## TL;DR

`sw/petalinux/build.sh` runs `rsync -a --delete project-spec/ → spikeyolo_petalinux/project-spec/` **before** `petalinux-config --get-hw-description`. The 22-line subset `project-spec/configs/config` **overwrites** the ~500-line auto-generated config from `petalinux-create -t project --template zynq`, wiping required keys like `CONFIG_SUBSYSTEM_ARCH_ARM=y`, `CONFIG_SYSTEM_ZYNQ=y`, etc. Result: `petalinux-config --get-hw-description` crashes because arch/soc are empty.

The comment on line 2 of the config — `"(subset — the rest is auto-generated by petalinux-config)"` — is incorrect about the order: the rsync clobbers the auto-gen rather than appending to it.

I (Cloud Claude) ran two iterative experiments in the build sandbox (Cloud-owned, see §4 of handoff) to prove this; details in §3.

## 4. Proposed Main fixes (pick one)

### Option A — append, don't overwrite, configs/config (smallest diff)

In `sw/petalinux/build.sh`, replace the unconditional rsync with one that excludes the config file, then append our subset:

```bash
# Step 2 (replacement):
rsync -a --delete --exclude 'configs/config' \
    "${SPEC_DIR}/" "${PROJ_DIR}/project-spec/"

# After step 4 (petalinux-config --get-hw-description) — re-apply our overrides:
cat "${SPEC_DIR}/configs/config" >> "${PROJ_DIR}/project-spec/configs/config"
run petalinux-config --silentconfig   # re-resolve with our overrides applied
```

**Risk:** duplicate keys in the resulting config — usually OK (last wins) but worth checking with `petalinux-config --silentconfig`.

### Option B — use `--add-config` flags (cleanest semantically)

Drop the static `project-spec/configs/config` subset entirely. Pass our overrides via flags:

```bash
run petalinux-config --get-hw-description="${XSA_PATH}" --silentconfig \
    --add-config 'CONFIG_SUBSYSTEM_PRIMARY_SD_PSU_SD_1_SELECT=y' \
    --add-config 'CONFIG_SUBSYSTEM_BOOTARGS_AUTO=y' \
    --add-config 'CONFIG_SUBSYSTEM_USER_CMDLINE="console=ttyPS0,115200 earlycon root=/dev/mmcblk0p2 rw rootwait cma=256M"' \
    --add-config 'CONFIG_SUBSYSTEM_ROOTFS_INITRAMFS=n' \
    --add-config 'CONFIG_SUBSYSTEM_ROOTFS_SD=y' \
    --add-config 'CONFIG_SUBSYSTEM_ROOTFS_EXT4=y' \
    --add-config 'CONFIG_SUBSYSTEM_INITRAMFS_IMAGE_NAME="petalinux-image-minimal"' \
    --add-config 'CONFIG_SUBSYSTEM_FPGA_MANAGER=y' \
    --add-config 'CONFIG_SUBSYSTEM_UBOOT_AUTOCONFIG=y'
```

(Skip MACHINE_NAME since no Digilent BSP, per ed2a1df.)

### Option C — drop the rsync of configs/config and use `sed` for inline overrides

In build.sh after get-hw-description:

```bash
sed -i 's|^CONFIG_SUBSYSTEM_ROOTFS_INITRAMFS=.*|CONFIG_SUBSYSTEM_ROOTFS_INITRAMFS=n|' \
    "${PROJ_DIR}/project-spec/configs/config"
# ...one sed per override key...
```

Ugliest, but most surgical.

**My recommendation:** Option B. It's the Xilinx-blessed way (`--add-config` is purpose-built for layered overrides) and removes the misleading config-subset file entirely.
