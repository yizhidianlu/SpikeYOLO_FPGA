## Root cause

`sw/petalinux/project-spec/meta-user/recipes-apps/spike-accel-app/spike-accel-app.bb`:

```bitbake
SRC_URI = "file://CMakeLists.txt \
           file://sdk/ \
           file://app/ \
           file://firmware/tiny_fpga_int8.bin \
           file://run_on_board.sh"

inherit cmake pkgconfig

DEPENDS = "libdrm v4l-utils"

# Runtime deps — libspike-accel ships from C2's sdk recipe (same CMake project
# here installs it). Bitbake will resolve via PROVIDES at packaging time.
RDEPENDS:${PN} += "libspike-accel"
```

But `meta-user/recipes-apps/spike-accel-app/files/CMakeLists.txt` (generated by `fetch_app_sources.sh`) bundles **both** sub-projects into a single CMake build:

```cmake
project(spike_accel_app_bundle LANGUAGES C CXX)
add_subdirectory(sdk)   # → builds & installs libspike-accel.so
add_subdirectory(app)   # → builds spike-accel-app, links libspike-accel.so
```

So this recipe **already produces** `libspike-accel.so` as part of `${PN}` (or a -dev sub-package via bitbake's default shlibs handling). The `RDEPENDS:${PN} += "libspike-accel"` line is asking bitbake to find a *separate* recipe that provides `libspike-accel`, and there isn't one — the comment's "C2's sdk recipe" was never split out.

Bitbake's auto-PROVIDES for SONAMEs does kick in (after do_package_qa), but **dependency resolution runs before that** — it doesn't yet know this recipe provides `libspike-accel`. So the queue planner halts.

---

## Two equally-clean fixes (Main picks)

### Option A — drop the RDEPENDS line (one-liner)

`do_package` + shlibs handling will auto-track the actual SONAME deps; the explicit `libspike-accel` listing is redundant for a bundle recipe.

```bitbake
# Delete this:
RDEPENDS:${PN} += "libspike-accel"
```

Rationale: the recipe both produces and consumes the .so internally; bitbake doesn't need a runtime-dep edge to schedule it.

### Option B — explicit PROVIDES

If you want the planner to treat this recipe as a satisfier of `libspike-accel`:

```bitbake
PROVIDES += "libspike-accel"
RPROVIDES:${PN} += "libspike-accel"
# (then RDEPENDS stays — bitbake will now find PROVIDES match)
```

Rationale: documents the intent ("this recipe DOES ship libspike-accel.so") for future readers, even if redundant for bitbake.

**My recommendation: Option A.** Simpler; removes incorrect intent claim (comment says "ships from C2's sdk recipe" but that recipe doesn't exist). Reflects reality: this is the one bundle recipe.

If Option B feels safer (more explicit), the comment block above should also be edited to drop the "C2's sdk recipe" line — there's only this one recipe.
