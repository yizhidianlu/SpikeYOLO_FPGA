## Error

After `bc0d89c` (FILES /opt/* fix) landed:

- Build advanced to **4577 attempted tasks** with most cached
- `spike-accel-app do_package: Succeeded` (the FILES glob fix worked)
- **Failed at `device-tree do_compile`**:

```
FATAL ERROR: Couldn't open "uio_config.dts": No such file or directory

Exception: subprocess.CalledProcessError: Command '['dtc', '-@', '-@', '-p',
  '0x1000', ..., 'system-top.dts.pp']' returned non-zero exit status 1.
ERROR: Task device-tree.bb:do_compile failed with exit code '1'
```

`dtc` is preprocessing `system-user.dtsi` which has at line 10:

```dts
/include/ "uio_config.dts"        /* auto-generated by tools/ci/gen_dts.py (C2 consumes) */
```

The file is supposed to land in `${WORKDIR}/` alongside `system-user.dtsi` and `spike-accel.dtsi`. It doesn't.

---

## Root cause

The file **exists** in this repo:

```bash
$ ls -la sw/driver/uio_config.dts
-rw-rw-r-- 1 ecs-user ecs-user 51 lines  # auto-generated by tools/ci/gen_dts.py from address_map.yaml
```

(51 lines, generated by C2 per contract 4 with C1's spike-accel.dtsi.)

But Main's `sw/petalinux/project-spec/meta-user/recipes-bsp/device-tree/device-tree.bbappend` only pulls in `spike-accel.dtsi`:

```bitbake
SRC_URI:append = " file://spike-accel.dtsi"
FILESEXTRAPATHS:prepend := "${THISDIR}/files:"
```

And `meta-user/recipes-bsp/device-tree/files/` only contains:

```
spike-accel.dtsi
system-user.dtsi
```

→ `uio_config.dts` is never copied into `${WORKDIR}` → `/include/ "uio_config.dts"` fails to resolve at dtc time.

---

## Fix (two changes)

### 1. `sw/petalinux/build.sh` — fetch `uio_config.dts` alongside app sources

Best place is in `fetch_app_sources.sh` (already deals with cross-tree copy):

```diff
 RECIPE="${ROOT}/sw/petalinux/project-spec/meta-user/recipes-apps/spike-accel-app/files"
 mkdir -p "${RECIPE}/sdk"   "${RECIPE}/app"   "${RECIPE}/firmware"
 rsync -a --delete "${ROOT}/sw/sdk/"  "${RECIPE}/sdk/"
 rsync -a --delete "${ROOT}/sw/app/"  "${RECIPE}/app/"

+# Device-tree: pull in the C2-generated UIO overlay so the C1 system-user.dtsi
+# can /include/ "uio_config.dts" at dtc time. Stored in sw/driver/ per
+# Contract 4 ownership; copied into meta-user/recipes-bsp/device-tree/files/
+# where the bbappend's FILESEXTRAPATHS picks it up.
+DT_RECIPE="${ROOT}/sw/petalinux/project-spec/meta-user/recipes-bsp/device-tree/files"
+mkdir -p "${DT_RECIPE}"
+cp "${ROOT}/sw/driver/uio_config.dts" "${DT_RECIPE}/uio_config.dts"
+echo "[fetch_app_sources] DT overlay: sw/driver/uio_config.dts -> ${DT_RECIPE}"
```

### 2. `sw/petalinux/project-spec/meta-user/recipes-bsp/device-tree/device-tree.bbappend` — add the file to SRC_URI

```diff
-SRC_URI:append = " file://spike-accel.dtsi"
+SRC_URI:append = " file://spike-accel.dtsi file://uio_config.dts"
 FILESEXTRAPATHS:prepend := "${THISDIR}/files:"
```

Both are needed: (1) puts the file under `files/`, (2) tells bitbake to copy it into `${WORKDIR}`.

Alternative for (1): hand-commit `uio_config.dts` into `meta-user/recipes-bsp/device-tree/files/`. Cleaner from a build-ordering perspective, but stale if address_map.yaml changes upstream. Going via fetch_app_sources is the "regenerate on every build" path.
