## Real root cause hypothesis (new)

The demotion is triggered by **usage pattern**, not interface declarations. Specifically: when Vitis HLS 2024.1 sees the top function body do:

```cpp
const sa_i32_t *w_off  = (const sa_i32_t *)w_pool;
const sa_i8_t  *w_data = w_pool + 30 * sizeof(sa_i32_t);
```

…it interprets `(const sa_i32_t *)w_pool` and `w_pool + N` as **address-arithmetic on a scalar pointer-typed register**, not as offset computation on a memory-mapped array. The 214-450 warnings ("Ignore address on register port") confirm: by the time the body uses `w_pool[...]`, Vitis has already classified `w_pool` as a register.

Or:

The DEFAULT interface mode for `T*` arguments in vitis 2024.1 `-flow_target vivado` is **`s_axilite`** (scalar register), and `#pragma HLS INTERFACE m_axi port=X` only **promotes** if it lands BEFORE the body's first use. Our `SA_AXI_MM` macros expand inline at function-body top — same scope as body code. There may be a lexical-order requirement (pragmas-before-body-code) that's being broken by the cast/pointer-arithmetic on lines 161-166.

## Suggested next moves (for Main / human)

### V1.3 — hardcoded compile-time offsets *(Main's pre-authorized fallback)*

Move offsets out of the AXI bus entirely. Generate `static const sa_i32_t W_OFF[30] = { ... }` in a codegen header (from `tools/quant/weight_packer.py`) and include it. The kernel uses `W_OFF[i]` (compile-time array, no m_axi). Top signature drops to 3 simple pool ptrs with no body-side cast/arithmetic:

```cpp
void sa_tiny_fpga_top(
    const sa_i8_t  *w_pool,
    const sa_i32_t *bias_pool,
    const sa_i8_t  *shift_pool,
    ...
){
    SA_AXI_MM(w_pool,     gmem2, 0x80000)
    SA_AXI_MM(bias_pool,  gmem2, 0x2000)
    SA_AXI_MM(shift_pool, gmem2, 0x1000)
    ...
    /* layer 0 */ sa_ms_downsampling(img_in, &w_pool[W_OFF_L00], &bias_pool[B_OFF_L00], &shift_pool[S_OFF_L00], ...);
    /* layer 1 */ sa_ms_downsampling(... &w_pool[W_OFF_L01], ...);
    ...
}
```

`W_OFF_L00..W_OFF_L29` are `#define`/`constexpr` from a tiny header autogenerated when weights are packed. **No runtime weight-layout flexibility**, but no Vitis demotion either. Probably what should have been done from the start; the dynamic-offsets-in-bus approach is over-engineered for M2.
